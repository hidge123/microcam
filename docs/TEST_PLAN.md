# Microcam 手动验收计划

自动测试覆盖脱敏、按小时聚合、日历日裁剪、提示词校验、AI Endpoint 安全规则、重试分类、数据库字段加密和文件权限。以下 macOS 权限、生命周期和性能行为需要在安装了完整 Xcode 的目标机器上手动验证。

## 准备

1. 使用 Release 配置构建 arm64 应用，并将 `Microcam.app` 放入 `/Applications`。
2. 在系统设置中移除此前的 Microcam 辅助功能和登录项授权，清除测试数据库与钥匙串项目。
3. 准备一个只用于测试的 OpenAI 兼容 Endpoint，以及可检查请求体的本机测试服务。

## 权限与首次引导

- 首次启动不应自动弹出任何 TCC 权限窗口。
- 在权限引导第二步明确点击申请后，才出现辅助功能授权提示。
- 拒绝权限后，应用仍记录前台应用与时长，数据库中标题为空，菜单栏显示受限状态。
- 授权后切换应用或窗口，应在事件触发后立即更新；不发送按键、鼠标、截图或 Apple Events。
- 在应用运行期间撤销权限，最迟 30 秒内降级为仅时长模式。
- 密码、钥匙串、1Password、Bitwarden、KeePassXC 默认只记录应用时长。

## 活动生命周期

- 应用切换时关闭旧时间段并开启新时间段；相同窗口不产生高频分段。
- 同一应用切换窗口标题时生成新的脱敏时间段。
- 达到配置的空闲阈值后停止计时；恢复输入后重新开始，不补记空闲时长。
- 锁屏、切换用户、屏幕休眠和系统睡眠时立即关闭时间段，唤醒后不补记睡眠时间。
- 跨本地午夜时在 00:00 分段，两个日期的汇总互不串日。
- 手动永久暂停在多个 30 秒检查周期后仍保持暂停；定时暂停到期后自动恢复。
- 退出前的最后时间段已落盘；强制终止最多损失最近 30 秒进度。

## 隐私与删除

- 使用包含邮箱、电话、IP、路径、URL、API Token、用户名和自定义敏感词的窗口标题进行验证。
- 在 UI、SQLite 主文件、WAL、系统日志和 AI 请求中搜索原始值，均不得出现。
- AI 请求只含小时、应用、脱敏活动和分钟数；API Key 只出现在 Authorization Header。
- 修改 AI Base URL 后，自动发送确认应自动关闭。
- 删除活动时，暂停中的旧时间段不会在下一个检查点重新出现。
- “彻底重置”后活动、日记、AI Key、自定义规则和设置全部恢复初始状态。
- Markdown 只写入用户在 `NSSavePanel` 中选择的位置，不保留目录访问权。

## AI 和调度

- HTTPS Endpoint 与 loopback HTTP 可用，远程 HTTP 在发出请求前被拒绝。
- 测试连接请求不包含活动；未确认数据目标时自动生成不运行。
- 00:05 生成上一完整日期；在计划时间休眠时，唤醒后补生成最近一个有活动的日期。
- 401/403 和响应格式错误不重试；429、5xx、断网最多尝试三次。
- 同一日期不会因多个定时器检查重复调用；重新生成失败时旧日记仍保留。
- AI 返回的 Markdown 可查看、复制和导出，数据库中无法检索到明文正文。

## 登录启动和窗口行为

- 启用登录启动后，系统登录项设置能看到 Microcam；重新登录后只出现菜单栏图标，不自动显示主窗口。
- 关闭主窗口后采集继续；菜单栏“退出”会刷新时间段并终止应用。
- 禁用登录项后重新登录，Microcam 不自动启动。

## 性能验收

使用 Release 构建，在目标 Mac 上用 Instruments 的 Time Profiler、Allocations 和 Energy Log 连续观察至少两小时：

- 静置期间平均 CPU 低于 0.5%。
- 常驻内存目标低于 100 MB，且没有持续增长。
- 空闲时没有网络请求；SQLite 写入频率不高于每 30 秒一次，应用/睡眠事件除外。
- 标题事件正常时即时更新；事件缺失时最迟约 30 秒更新。
- Energy Impact 保持 Low，且不存在持续高频 Timer、事件 Tap 或屏幕采集会话。
